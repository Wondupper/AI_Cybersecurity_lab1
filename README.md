# Подмена голоса (Voice Conversion): bdl → slt

Лабораторная работа №1 курса «Киберустойчивость систем ИИ 2026».
Направление: Speech Processing. Среда используется во всех следующих ЛР.

## Задача модели
- **Задача:** преобразование голоса: речь диктора `bdl` (мужской) превращается в речь голосом `slt` (женский), содержание фразы сохраняется.
- **Вход:** WAV-файл с короткой речью (16 кГц, моно).
- **Выход:** WAV-файл с тем же содержанием голосом целевого диктора.
- **Пользователь:** приложение или веб-страница, отправляющая аудио в API (ЛР4).
- **Предварительная метрика:** MCD (расстояние между спектральными признаками преобразованной и настоящей речи цели); обоснуем в ЛР2.

## Датасет
CMU ARCTIC v0.95 (Kominek & Black, 2004), дикторы `bdl` и `slt`. Источник: http://festvox.org/cmu_arctic/ (скачан по HTTP, HTTPS не сработал).

| Параметр | Значение |
|---|---|
| Объектов | 2 × 1132 WAV-файла (параллельные фразы) |
| Формат | 16 кГц, моно, PCM_16, английская речь |
| Длительность | bdl 51,0 мин; slt 56,6 мин |
| Классы | нет (преобразование голоса); есть два диктора |
| SHA256 архивов | `26b91aaf48b2799b2956792b4632c2f926cd0542f402b5452d5adecb60942904` (bdl), `7c173297916acf3cc7fcab2713be4c60b27312316765a90934651d367226b4ea` (slt) |

Особенности (ноутбук `notebooks/01_dataset_eda.ipynb`, график `docs/durations.png`):
- Набор фраз полностью совпадает у обоих дикторов (1132 из 1132).
- `slt` читает медленнее: средняя фраза 3,0 с против 2,7 с, поэтому записи надо выравнивать по времени (DTW).
- Пик амплитуды у всех файлов 0,650 (по-видимому, нормировка авторов), перегруженных файлов нет.
- Для `bdl` в файле транскрипций разобралась 1131 строка из 1132:
- Лицензия: файла лицензии в архивах нет; по описанию отчёта авторов и сторонней документации база свободная с указанием авторства. Это не юридическая оценка.

### Почему `.env` нельзя хранить в репозитории
Всё, что попало в коммит, остаётся в истории и доступно каждому, у кого есть доступ к репозиторию (а у публичного — всем). Удаление файла в следующем коммите не стирает его из истории, `.gitignore` не действует на уже закоммиченные файлы, а публичные репозитории автоматически просматривают боты, ищущие ключи. Поэтому пароли и токены хранятся в переменных окружения или в хранилище секретов, а скомпрометированный ключ придётся перевыпускать.

## Базовая модель преобразования голоса (bdl → slt)

Признаки: F0 и 24 кепстральных коэффициента WORLD (шаг 5 мс). Кадры выравниваются DTW по коэффициентам 1–23.
Модель: совместная гауссова смесь (JD-GMM), 16 компонент, 100 000 кадров train, seed 42, без временного сглаживания.
Метрика: MCD по кепстральным коэффициентам WORLD (не классический мел-кепстр), коэффициент 0 не учитывается; меньше значит лучше.

Результат на тесте (113 фраз): JD-GMM 7,63 дБ; копия источника 12,18 дБ; среднее вектора цели 14,06 дБ. Подробности в `metrics/baseline.json`.

### Команды
    python src/make_split.py                 # разбиение 906/113/113 по фразам -> data/splits.json
    python src/extract_features.py           # признаки -> data/features/
    python src/f0_stats.py                   # статистика F0 по train -> models/f0_stats.json
    python src/align.py train val test       # DTW -> data/aligned/
    python src/train_gmm.py 16 100000        # обучение, MCD на val; перезаписывает models/gmm_M16.npz
    python src/evaluate.py [модель]          # единственная оценка на test -> metrics/test_eval.json (baseline.json не трогает)
    python -m pytest tests/ -q               # 12 тестов
    python -m bandit -r src/                 # статический анализ
    python src/predict.py in.wav out.wav     # преобразование одной записи
    sha256sum -c models/SHA256SUMS           # целостность модели

### Пределы входа
WAV, PCM 16 бит, 16 кГц, один канал; длительность до 10 с (максимум в данных 5,73 с); размер файла до 1 МБ (10 с занимают около 320 КБ).
Заголовок проверяется до чтения данных; затем проверяются декодирование и отсутствие NaN/Inf. Ограничение размера файла не заменяет ограничение длительности. При отклонении бросается `InputError`, модель не вызывается.
Параметры модели хранятся в `.npz` и загружаются с `allow_pickle=False`, исполняемый код при загрузке не выполняется.

### Ограничения
- MCD считается на выравнивании источник–цель, а DTW строился по тем же признакам, поэтому оценка оптимистична.
- Звучание проверено на слух только на одной фразе.
- Слабый шум (SNR 30 дБ) сильно меняет результат (MCD между результатами 8,0 дБ); изменение громкости почти не влияет (0,4 дБ).
- `setuptools` закреплён на 80.10.2: `pyworld` импортирует `pkg_resources`, которого нет в 84.1.0. `pip-audit` сообщает 2 уязвимости setuptools (PYSEC-2026-3447, GHSA-xmj3-9gf7-h52w); риск принят, пакет используется только при импорте `pyworld`.

## CI/CD и проверки качества

Pipeline (`.github/workflows/ci.yml`) запускается при push и pull request. Три задания идут друг за другом: следующее стартует только после успешного предыдущего.

| Задание | Шаги |
|---|---|
| `quality` | Ruff, Bandit, pytest, аудит зависимостей |
| `gates` | проверка SHA256 модели и контрольной выборки, data gate, model gate |
| `image` | сборка образа, запуск без root, smoke, Trivy (Dockerfile и образ) |

Отчёты (pytest, Bandit, pip-audit, model gate, Trivy, версии инструментов, commit и хэши) сохраняются как артефакты запуска, в том числе при сбое. Права CI: только чтение кода, секреты не используются. Версии действий закреплены коммитами, у заданий есть ограничение времени.

### Зависимости
- `requirements-runtime.txt` - зависимости приложения и образа (всё закреплено);
- `requirements-dev.txt` - инструменты проверок (Ruff, Bandit, pytest, pip-audit);
- `requirements.txt` - полный `pip freeze` окружения ВМ.

### Политика безопасности (`configs/security_policy.json`)
- **pip-audit - строгая политика:** отказ при любой находке, кроме двух записей setuptools 80.10.2 (PYSEC-2026-3447, severity medium; GHSA-xmj3-9gf7-h52w, severity low - по osv.dev). Причина: версия закреплена, так как `pyworld` импортирует `pkg_resources`, которого нет в setuptools 84.1.0. Любая новая находка, в том числе с неизвестной severity, останавливает сборку. Пакет из requirements, не попавший в отчёт, тоже считается непроверенным. Код возврата pip-audit передаётся в `src/security_gate.py`, пустой или повреждённый отчёт - отказ.
- **Trivy:** образ блокируется при находках CRITICAL и UNKNOWN (`trivy image --severity CRITICAL --exit-code 1` плюс проверка отчёта). Исключения: одна запись по `perl-base` (CVE-2026-82560, высокая серьёзность, исправления в Debian пока нет, perl в контейнере не используется), причина записана в `configs/security_policy.json`. Пакеты ОС обновляются при сборке образа. Ошибка скачивания базы или сканирования - отказ, а не «уязвимостей нет». Dockerfile проверяется командой `trivy config --exit-code 1`.

### Контрольная выборка и data gate
`data/control/control_val.npz`: 20 фраз из val (выровненные пары кадров), описание и схема - в `data/control/README.md`, эталонный SHA256 - в `data/control/SHA256SUMS`. Правила - `configs/data_gate.json` (обязательные массивы, типы, форма (N, 24), NaN/Inf, границы значений, число фраз и кадров, хэш и версия данных). Нарушение даёт код возврата 1.

### Model gate
Метрика MCD (меньше - лучше), кандидат оценивается на контрольной выборке тем же кодом `src/mcd.py`. Проходит при `candidate <= baseline * 1.05`. Baseline и допуск лежат в `metrics/ci_baseline.json` и автоматически не перезаписываются (`--init-baseline` отказывается работать, если файл есть). Отсутствующая, нечисловая метрика, плохой baseline, другая версия данных или другой хэш выборки - отказ. Результат сравнения и код возврата пишутся в `reports/model_gate.json`. Gate не заменяет финальную оценку на test (`metrics/baseline.json`, ЛР2).
